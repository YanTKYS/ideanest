# 運用メモ (v0.4.0)

普段使う人向けの、小さな運用上の注意。

## ファイルの保存場所

- `.ideanest` ファイルの置き場所はユーザーの自由。
- 推奨は **OneDrive / Dropbox / Google Drive 等の同期フォルダではない場所**。
  - 同期中のロックや競合保存で `.bak` が増殖したり、編集中の保存が失敗する恐れがあるため。
  - 同期したい場合は、IdeaNest を閉じてから同期させる運用にする。
- バックアップを取りたい場合は、`.ideanest` と `.ideanest.bak` の **両方** を一緒にコピーしておくと安全。

## `.bak` の意味

- `保存` した瞬間に、それまでの内容を `(ファイル名).ideanest.bak` として残す。
- つまり `.bak` は **1 つ前の保存内容**。
- 連続して保存した場合、`.bak` も上書きされる点に注意。世代管理はしない。
- 操作を間違えた直後であれば、`.bak` を `.ideanest` にリネームすれば 1 手前に戻せる。

## 自動保存 (v0.4.0)

- 既存の `.ideanest` ファイルを開いている場合のみ、編集後 2 秒で自動保存される。
- 新規未保存状態 (タイトルバーに `(未保存)` と表示) では自動保存されない。
  最初の `名前を付けて保存` でファイルパスを決めてから自動保存が動き始める。
- 画面下部に保存状態が表示される。
  - `新規ファイル` / `未保存 (新規ファイル)`: まだ保存先が決まっていない
  - `未保存の変更あり`: 自動保存待機中
  - `自動保存中...`: 保存処理中
  - `自動保存しました HH:mm`: 直前の自動保存に成功した時刻
  - `保存済み`: 開いた直後で未編集
  - `自動保存に失敗しました`: 後述
- 自動保存に失敗した場合 (例: `.ideanest` が読み取り専用、フォルダの権限が無い、ドライブが切断された)
  - 画面下部の表示が `自動保存に失敗しました` になる
  - タイトルバーの `*` は消えず、未保存状態が維持される
  - MessageBox は出ないため、編集を続けながら原因を解消してから `Ctrl+S` で再試行する
  - 失敗状態のまま閉じようとすると、終了時確認ダイアログが出る
- 自動保存時も `.bak` (1 つ前の保存内容) が更新される。世代バックアップは行わない。
  - `.bak` を「数分前の状態に戻す」用途で使いたい場合は、自動保存前に手動で別フォルダにコピーしておく運用が安全。

## 終了時の挙動

- `*` がタイトルバーに付いていれば未保存。
- 自動保存済みで `*` が無ければ、終了時確認は出ずに閉じる。
- 未保存変更がある (新規未保存状態 / 自動保存失敗) 場合は、保存するか / 破棄するか / キャンセルするかを聞かれる。
- 強制終了 (タスクマネージャ) で落とすと、変更は反映されない。

## トラブル時の確認

| 症状 | まず見るところ |
| --- | --- |
| アプリが起動しない | `.NET 8 SDK` (またはランタイム) が入っているか / `dotnet --version` |
| `.ideanest` を開いてエラー | 同フォルダに `.ideanest.bak` があるか / なければテキストエディタで先頭行を確認 |
| カードが消えた | アーカイブ表示の状態 / 検索文字列が残っていないか / タグフィルタが残っていないか |
| 保存しても反映されない | タイトルバーに `*` が消えたか / ファイルの更新日時が新しくなっているか |
| 自動保存されない | タイトルバーが `(未保存)` のままになっていないか (新規未保存状態では自動保存しない) / 画面下部が `自動保存に失敗しました` になっていないか |

## 想定していないこと

- 同じ `.ideanest` を 2 つの IdeaNest インスタンスで同時に開くことは想定していない。
- ネットワーク越しの共同編集は対象外。
- `.ideanest` を別アプリで編集している間にアプリ側で保存すると、後勝ちで上書きされる。
